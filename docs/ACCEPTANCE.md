## 실패 재현과 구조 정리

### 화면 테스트 자체에서 발견한 실패

첫 전체 `npm run test:e2e` 결과는 18개 중 14개 통과·4개 실패였다.

- `10,000원`이 실제 지표와 손계산 설명 두 곳에 있어 locator가 모호했다.
- 30일 모바일 검사는 초기 로딩과 반응형 레이아웃 이동 중 버튼 actionability를 기다리다 timeout 됐다.

기능은 바꾸지 않고 다음과 같이 테스트만 정리했다.

- `10,000원` locator를 exact match로 변경했다.
- 초기 7일 로딩 완료 후 기간 버튼을 누르도록 했다.
- 이미 특정 버튼과 로딩 완료를 확인한 모바일 기간 전환은 강제 클릭으로 상태 전환 자체를 검사했다.
- 30일 날짜별 요청에 맞게 해당 시나리오 timeout을 늘렸다.

격리 모바일 재검사는 1개 통과했고, 이어서 전체 `npm run test:e2e` 18개가 모두 통과했다.

### PRD 기능 차이 재현

임시 Playwright 테스트로 AC 5·6·7·8·13을 확인했고 5개 모두 실제 실패했다. 이 항목들은 상태 공유, 신규 차트, 선택 기능, 신규 지표와 집계 정책 변경이 필요하므로 **기능 변경 없이 리팩터링만으로 통과시킬 수 없다**. 사용자의 제한을 지키기 위해 이번 검증에서는 제품 기능을 변경하지 않았고 임시 재현 파일은 제거했다.

## 최종 결론

F1의 핵심 조회·검색·상태 구분, 숫자 검증, live API/DB 저장본 정합성, 비밀값 경계는 확인됐다. 그러나 PRD 기준 F2의 공유 날짜·관객 추이·Top 10·필수 보조 지표·빈 날짜 집계 정책이 미충족이고, KOBIS 공식 약관과 DB 캐시 설계가 충돌한다. 따라서 현재 버전은 **PRD 전체 인수 통과가 아니며 배포 보류**가 정확한 판정이다.
