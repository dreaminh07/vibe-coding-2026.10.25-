# 박스오피스 데이터 정확성 검증

변경한 데이터 경로의 입력·기대값·실제 결과를 비교해 회귀 여부를 확인한다. 단순 화면 수정이라도 날짜 범위, 표시 값 변환, 차트 데이터나 집계 결과에 영향을 주면 적용한다. 이 Skill 자체를 작성·편집하는 일은 검증 워크플로 실행 요청으로 간주하지 않는다.

## ① 입력과 기준 찾기

1. 저장소 루트를 찾고 [AGENTS.md](../../../AGENTS.md), [PRD.md](../../../PRD.md), [ARCHITECTURE.md](../../../ARCHITECTURE.md)를 읽는다. DB 변경이면 [ERD.md](../../../ERD.md), 기술 결정 변경이면 [ADR.md](../../../ADR.md)도 확인한다. 링크는 이 Skill 파일 위치 기준이다.
2. 변경 파일과 호출 경로를 확인해 파싱·저장·집계 중 영향을 받는 구간과 관련 PRD AC를 기록한다. 데이터 계약이나 기대값이 문서와 다르면 불일치를 먼저 드러내고, 임의로 현재 구현을 정답으로 삼지 않는다.
3. `package.json`의 실제 스크립트, 기존 테스트·픽스처, DB 마이그레이션을 확인한다. 명령이 없으면 `미정`으로 기록하고 존재한다고 가정해 실행하지 않는다. 검증을 위해 무관한 프레임워크를 도입하지 않는다.
4. 정상 응답·정상 빈 응답·오류 응답과 필요한 경계값을 가상 데이터로 준비한다. 기대 결과는 PRD 규칙과 수작업 계산 또는 독립 SQL 등으로 정하며, 변경한 함수의 출력을 그대로 기대값으로 복사하지 않는다.
5. `KOBIS_API_KEY`, `SUPABASE_SECRET_KEY`의 실제 값을 읽어 출력하거나 픽스처·로그에 넣지 않는다. 기본 검증은 외부 호출 없는 가상 응답과 격리된 테스트 DB를 사용한다. 검증 요청을 운영 DB 쓰기나 배포 권한으로 해석하지 않는다.

## ② 변경에 맞춘 검사 선택

아래에서 변경으로 영향을 받는 항목만 선택하고 필요한 하위 경로까지 검증한다. 제외한 항목은 적용 대상이 아닌 이유를 짧게 밝힌다. 파싱 결과가 DB·집계에 전달되는 계약을 바꾸었다면 관련 저장·집계 검사도 포함한다.

| 변경 구간 | 선택할 검사 | 판단 기준 |
| --- | --- | --- |
| 응답 파싱·숫자 정규화 | 일간·주간·주말 중 영향받는 응답 형태, 8개 필드 매핑, 실제 집계 기간 확인 | `movieCd`, `movieNm`, `rank`, `openDt`, `salesAmt`, `audiCnt`, `salesAcc`, `audiAcc`가 계약에 맞게 정규화됨. 영화 코드는 문자열, 빈 개봉일은 `null` |
| 숫자 검증·직렬화 | `"0"`, `"9"`, `"100"`, 잘못된 문자열·빈 필수값·음수·안전 정수 초과값 | 0은 유효, 잘못된 값은 오류. 순위는 안전한 양의 정수, 금액·인원은 정확한 정수 계산과 DTO 문자열 왕복을 보장. DB 범위를 넘으면 거부 |
| 응답 상태 분기 | 정상 빈 배열, HTTP 성공 본문 안의 API 오류, 결과 배열 누락·파싱 실패, 검색 불일치 | 빈 배열만 `empty`. API·형식 오류는 오류와 재시도. 원본 목록이 있는 검색 불일치는 검색 안내로 구분 |
| DB 저장·JOIN | 같은 조회 조건 재저장, 동일 영화 중복, 동명 영화, 다른 날짜·유형, 영화명 수정, JOIN 결과 | 조회 기간 고유키와 실적 복합 PK·FK 유지. 중복 없이 값 갱신. 다른 날짜·유형 실적이 섞이지 않고 영화는 코드로 연결 |
| 트랜잭션·갱신 | 중간 저장 실패, 재조회 시 순위에서 빠진 영화, 실적 있음→정상 빈 응답 변경 | 실패 시 전체 롤백. 갱신 후 오래된 실적이 남지 않음. `ok`는 실적 1개 이상, `empty`는 기간 행만 있고 실적 0개 |
| 캐시 | 고정 시각으로 유효·정확한 만료 경계·미스·버전 불일치, 외부 실패, DB 실패 확인 | `now < expires_at`만 유효. 정상 1시간·빈 응답 5분의 초기 TTL 유지. 오류 저장·만료 연장·만료 데이터 대체 제공 금지. DB 조회 실패와 미스 구분 |
| 기간·날짜 선택 | 종료일 포함 7/14/30일, 월·연도 경계, 한국 시간 전일, 미래 날짜, 주간·주말 범위 | 정확한 날짜 수와 범위. 인사이트는 일간만 사용하고 목록 유형·검색어와 독립 |
| 지표·Top 계산 | 기간 매출·관객 합계, 일평균, Top 5/10, 동률·동명 영화, 누적 수치 | 영화 코드로 묶고 매출↓→관객↓→코드↑ 정렬. 일평균은 데이터 보유 일수로 나눠 원 단위 반올림. 누적값은 합산하지 않음 |
| 부분 데이터·실패 | 일부 날짜 정상 빈 응답, 전체 빈 응답, 한 날짜 요청 실패 | 빈 날짜는 차트 공백이며 합계·분모에서 제외. 전체 빈 응답은 데이터 없음. 한 날짜라도 실패하면 완성된 부분 집계 표시 금지 |

금액·인원의 JavaScript 계산은 `bigint`, JSON 전달은 정확한 10진 정수 문자열인지 확인한다. 차트 좌표의 `number` 변환은 안전 범위를 검사하며 정밀도 손실을 숨기지 않는다.

지표 검사의 기준 데이터가 필요하면 ERD의 영화 2개·3일 예시를 사용한다. 기대 합계는 별빛 항해 340,000,000원·34,000명, 가을의 편지 310,000,000원·31,000명이며, 전체 650,000,000원·65,000명, 일평균 216,666,667원이다. 이 3일 예시는 계산 단위 검사에 사용하고 서비스의 허용 기간 7/14/30일을 3일로 바꾸지 않는다. 캐시 검사는 현재 실제 시각에 의존하지 않도록 시계를 고정한다.

검사는 기존 테스트 도구로 실행한다. 저장·JOIN·트랜잭션 제약은 가능하면 격리된 PostgreSQL에서 확인하고, DB 모킹만 수행했다면 실제 DB 제약까지 통과했다고 보고하지 않는다. 테스트 DB가 없으면 실행 가능한 순수 함수·계약 검사는 계속하고 DB 통합 검사는 `미실행`으로 남긴다. 변경에 필요한 실제 `build`, `lint`, `typecheck`, `test` 스크립트만 실행하며, 이 명령들의 성공이 데이터 기대값 검사를 대신하지는 않는다.

## ③ 결과와 중단 기준

각 검사에 입력 또는 픽스처, 기대값, 실제 결과, 실행 명령이나 수동 확인 방법을 연결해 보고한다. 실제 실행 상태와 적용 범위를 다음처럼 구분한다.

| 결과 | 판정 | 보고할 근거 |
| --- | --- | --- |
| 통과 | 검사를 실제 수행했고 관측한 결과가 사전에 정한 기대값과 일치 | 명령·대상, 비교한 값 또는 확인한 불변조건, 성공 결과 |
| 실패 | 검사를 수행했으나 기대값·제약과 불일치하거나 검사 자체가 실행 중 오류로 종료 | 재현 입력, 기대값과 실제값 또는 오류, 영향 범위. 환경 문제면 제품 오류와 구분 |
| 미실행 | 필요한 검사를 실행하지 못했거나 검증 수단이 아직 없음 | 누락 사유와 필요한 조건. 도구·코드·DB·명령 부재를 통과로 바꾸지 않음 |

- 적용 대상이 아닌 검사는 실행 대상에서 제외하고 이유만 적는다. 필요한 검사를 제외 항목으로 숨기지 않는다.
- 관련 검사가 모두 통과하고 필요한 미실행 항목이 없으면 해당 범위의 검증을 마친다. 관련 변경이나 새 실패가 없으면 같은 검사를 불필요하게 반복하지 않는다.
- 실패하면 해당 경로를 통과했다고 보고하지 않는다. 요청 범위에서 원인을 수정한 뒤 실패 검사와 직접 영향을 받는 검사를 다시 실행한다. 해결되지 않으면 실패와 남은 문제를 명시한다.
- 기준 문서 충돌로 기대값을 정할 수 없거나 운영 DB 쓰기·비밀 노출이 필요한 방식만 남으면 해당 검사를 중단한다. 독립적으로 가능한 검사는 계속하고, 중단한 검사는 `미실행`과 사유·필요한 결정으로 보고한다.
- 스크립트·DB 부재 때문에 새 앱을 만들거나 운영 환경을 변경하지 않는다. 계획·코드 검토만으로 실행 검증을 대체했다고 주장하지 않는다.
- AGENTS.md에 따라 `일반 모드 작업 계획`과 실제 `Plan Mode 계획 결과`를 구분한다. 계획, 구현 변경, 검증 완료를 혼동하지 않는다.

보고 형식:

```text
변경 범위: <파싱 / 저장 / 집계, 관련 파일·AC>
통과: <검사 — 명령·입력 — 기대값과 관측 결과>
실패: <검사 — 기대값 / 실제값 또는 오류 — 영향> 또는 없음
미실행: <필요한 검사 — 사유 — 실행에 필요한 조건> 또는 없음
제외: <적용 대상이 아닌 검사와 이유>
남은 문제: <미해결 영향 또는 없음>
```
